# Fixture corpus

Real `d8` output, checked in, generated by [`tools/gen-fixtures.sh`](../tools/gen-fixtures.sh).
These exist *before* the parsers (TODO Phase 0) so that format assumptions are
tested against reality rather than memory.

```
workloads/          JS inputs (see below)
arm64-v15.2.0/      tip of tree, arm64      -- primary target
arm64-v14.9.0/      older V8, same arch     -- version axis
x64-v14.9.0/        same older V8, x64      -- architecture axis
<dir>/manifest.json exact command line, size, sha256, reproducibility per file
large/              multi-hundred-MB perf trace (git-ignored, see tools/gen-large-trace.sh)
```

Splitting the axes is the point: a difference between `arm64-v15.2.0` and
`arm64-v14.9.0` is a V8 version change; a difference between `arm64-v14.9.0` and
`x64-v14.9.0` is an architecture difference. Conflating them makes every
regression ambiguous.

## Files are ANSI-colored and that is deliberate

d8 does not check `isatty`, so a piped trace carries SGR escapes mid-line. The
fixtures preserve them byte for byte, because that is what the parser and the
raw view have to cope with. Use `sed 's/\x1b\[[0-9;]*m//g'` when eyeballing.

## Workloads

| File | Targets |
| :-- | :-- |
| `simple.js` | smallest Maglev graph; the baseline parser fixture |
| `deopt-eager.js` | wrong-map eager deopt, then reoptimization (two instances of one function) |
| `osr.js` | OSR compilation with a bytecode offset |
| `inlining.js` | inlining decisions, including one rejected callee |
| `poly.js` | monomorphic → polymorphic → megamorphic feedback |
| `truncation.js` | float64 arithmetic behind `\| 0`; the truncation phases |
| `gc.js` | allocation churn for `--trace-gc` |
| `mixed.js` | several functions tiering at different times, one flip-flopping |

## Naming

`<flag-slug>.<workload>.log`, e.g. `maglev-graphs+inlining.inlining.log` is
`--print-maglev-graphs --trace-maglev-inlining` on `inlining.js`. The
`manifest.json` in each directory has the exact argv.

## Reproducibility

The generator runs every command twice and records whether the two runs are
byte-identical. About half the fixtures per build are stable; the rest carry
wall-clock timings, native pointers, PIDs or thread interleaving. Prefer the
stable ones for golden tests, and see
[../docs/spike-findings.md](../docs/spike-findings.md) §10 for what varies and
why.

## Regenerating

```bash
tools/gen-fixtures.sh
git diff fixtures/     # exactly what the printer change did
```
